# 语言自适应规则

在整个 Lumina 工作流中分别维护两个变量：

- `interaction_language`：控制用户可见的全部内容。
- `story_language`：控制剧本、对白、旁白、标题卡、字幕（若用户要求）和 TTS。

## interaction_language

根据用户最新一条直接指令确定。不要因为附件、引用、粘贴剧本、参考资料、代码块、元数据、专有名词、文件内容或工具输出使用了另一种语言，就改变交互语言。

混合语言消息按以下顺序处理：

1. 用户明确指定交互语言时遵循该指令。
2. 否则使用承载最新实质请求的语言。
3. 仍无法判断时沿用已建立的对话语言。

所有用户可见的标题、说明、提问、选项、推荐标记、节点描述、计划、进度、确认、错误、恢复说明和最终交付摘要都使用 `interaction_language`。

## story_language

按以下优先级确定：

1. 用户明确指定的内容语言。
2. 修改既有剧本时，保留该剧本的语言。
3. 否则使用 `interaction_language`。

全片剧本、对白、旁白、标题卡和声音文本统一使用 `story_language`，除非用户明确要求多语言内容。若底层生成模型要求另一种 Prompt 语言，只翻译节点内部的隐藏技术指令，不改变用户可见界面或最终叙事内容的语言。

## 变更传播

用户在中途修改语言时：

- 更新 `SPEC-vN` 并递增版本。
- 将所有未生成的可见文本与 Prompt 切换到新语言。
- 对已批准的剧本、对白、旁白或标题卡，先展示语言迁移范围并重新确认。
- `story_language` 变化会使相关 TTS、标题卡和依赖视频标记为 `stale`；按依赖顺序重新生成。
- 不因交互语言变化自动重生成已经确认的故事媒体，除非故事语言也发生变化。
